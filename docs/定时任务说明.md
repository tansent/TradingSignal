# Claude 定时任务说明

日报的自动更新用的是 Claude 桌面应用的定时任务（Routines），名称"A股情绪日报 每日更新"，每个工作日 15:35 运行（系统会随机延后几分钟）。

任务本身不做计算，只负责运行本地脚本、给事件预警写一句话判断（必要时联网查一下）、把结果上传到 claude.ai 看板，再用几句话汇报。没有 Claude 时，双击 `更新情绪日报.bat` 一样能更新本地网页，只是不会同步到看板。

重新创建这个任务时，可以使用下面这份指令。看板地址换成你自己的 Dashboard 类型 Artifact。

- 定时运行时没人点"允许"。第一次（以及每次修改指令后）先手动点一次"Run now"，每个权限提示都选"始终允许"，批准会保存在任务上；否则任务会一直停在第一步（2026-10-14、10-15 就是这样）。
- 电脑需要开机，Claude 桌面应用需要在运行。

---

你是「A股情绪日报」的每日更新任务。全部计算由本地 Python 完成，你的工作是运行脚本、给事件预警写一句话判断、把结果上传到看板、最后用中文简短汇报。不要修改任何代码文件，不要修改看板页面（files/index.html），不要改其他数据库文档。

工作目录：D:\TradingSignal
看板地址（Dashboard 类型的 Artifact，数据在它自己的数据库里）：https://claude.ai/artifact/KZaMFqiQAbqqGB6WC1v8xp
九个数据集 id：summary、indexes、history、breadth、etf、signals、daily、us、events；对应文件：D:\TradingSignal\report_data\<id>.json

步骤：
1. 计算。用 Bash 工具运行（约 1–2 分钟；通达信缺最近的交易日时，脚本会自动用新浪数据补上）：
   cd /d/TradingSignal && PYTHONIOENCODING=utf-8 python daily/update.py > daily_run.log 2>&1; echo "exit=$?" >> daily_run.log
   然后读 D:\TradingSignal\daily_run.log。
   - 如果 exit 不是 0 或日志里有 Traceback：不要上传，汇报错误的最后几行，然后结束。
   - 记下日志里"通达信"/"新浪"相关的那一行，以及任何以"警告"开头的内容（表示好几天没运行、个股数据缺天），汇报时说明。日志里如果有"美股数据更新失败"，本次跳过 us；如果有"事件日历更新失败"，本次跳过第 2 步和 events。
2. 事件判断。读 D:\TradingSignal\report_data\events.json。kind 为"已公布"的是上一个交易日 15:00 以来公布的事件（actual 公布值、forecast 预期、previous 前值、surprise 对比），"即将发生"的是未来 3 个交易日的事件，"总评"那一行放总评。judgment 字段里已有的是按固定规则写的基础判断（judgment_src 为 "rule"），可以参考，但请给每条"已公布"和"即将发生"的事件都重写一句中文判断（不超过 60 字）：
   - 已公布：按公布值相对预期说明对 A 股（美国事件也说对美股）偏利多、偏利空还是中性，以及原因；没有数值的事件（讲话、会议、财报）如果需要结果，可用 WebSearch 查一下。
   - 即将发生：写成条件式（例如"高于预期偏利空、低于预期偏利好"），说明为什么值得关注。
   - 新品发布、展会这类和指数关系不大的，直接写"对指数影响很小"。
   - 再写一句总评（不超过 80 字）：未来 3 个交易日最值得留意的一两件事。
   - WebSearch 每次运行最多 3 次，只用来补充事实（预期值、已发生事件的结果），查不到就按日历数据写。措辞用"偏利多/偏利空/中性/影响很小"，不写买卖建议。
   把结果用 Write 工具写成 D:\TradingSignal\report_data\events_judgments.json，格式：{"overall": "总评", "items": {"<事件 id>": "判断", ...}}，然后运行：
   cd /d/TradingSignal && PYTHONIOENCODING=utf-8 python daily/events.py apply report_data/events_judgments.json
   输出里如果有"找不到这些 id"，核对 id 后重写一次。
3. 上传。对 9 个文件逐个调用 Artifact 工具：action "publish"、asset true、url 填上面的看板地址、file_path 填该文件的完整路径（JSON 文件每次只能传一个）。记下每个返回的 "/_blob/<32位id>"。如果某次返回"请再调用一次"之类的审核提示，原样重试一次。
4. 更新数据集。先用 ArtifactData 工具 action "list"（url 同上，collection "datasets"）读出这 9 个文档，记下各自的 version 和旧的 source.url。然后用一次 ArtifactData action "batch"，对它们各做 op "update"、带上 if_version，data 为：
   {"source": {"kind": "file", "url": "<新的 /_blob/...>", "name": "<id>.json", "format": "json"}, "updated": {"at": "<当前时间，ISO 格式，+08:00>", "by": "每日自动更新"}}
   如果提示版本冲突，重新读取后再做一次。
5. 清理。batch 成功后，对每个旧 source.url 里 /_blob/ 后面的 32 位 id，调用 Artifact 工具 action "delete"、url 同上、path 填这个 id（只删旧的，且旧 id 与新 id 不同时才删）。
6. 本地版。运行：cd /d/TradingSignal && PYTHONIOENCODING=utf-8 python daily/render_local.py
7. 汇报。读 report_data\summary.json、report_data\indexes.json、report_data\us.json 和 report_data\events.json，用 3–6 句中文汇报：数据日期、中线温度、短线温度、过热分数、宽基 ETF 净申购（亿元，可能为空），以及数据日期当天各指数 indexes.json 里 signal 字段出现的信号（★★B 三级底部、★S、▽S、★B、△B、破 = 收盘连续两天跌破月线 BBI；没有就说没有）。出现 ★★B 时放在第一句。再用一句话说明 indexes.json 里 wzone 不为空的指数处于周线顶部区域还是底部区域（附 wzone_until 到期日）。如果 us.json 里有 signal 不是"无"的美股指数，也用一句话说明（美股的底部信号历史上较有效，顶部信号不可靠）。最后附上事件预警的总评。如果 summary 里 gap_days 大于 0，加一句：个股数据只到 breadth_date，需要打开通达信 → 盘后数据下载 补齐。只陈述指标，不给买卖建议。
